۱. مبانی سیستم و سخت‌افزار

System Architecture & Hardware

معماری سیستم و پردازنده

لینوکس روی معماری‌های متنوعی اجرا می‌شود. شناسایی معماری روی انتخاب بسته و دستورات تأثیر می‌گذارد. پرکاربردترین‌ها: x86_64 (سرورها) و aarch64 (ابر و ARM).

BIOS در برابر UEFI

UEFI مدرن‌تر است، از پارتیشن GPT و Secure Boot پشتیبانی می‌کند و پارتیشن ESP (EFI System Partition) دارد.

ویژگیBIOS (سنتی)UEFI (مدرن)

فرآیند بوت لینوکس

روند بوت: POST/UEFI ← Bootloader (GRUB2) ← Kernel ← initramfs ← systemd (PID 1) ← Target. GRUB2 فایل تنظیماتش /etc/default/grub است.

عیب‌یابی بوت
journalctl -b -p err          # خطاهای بوت اخیر
systemd-analyze               # زمان کل بوت
systemd-analyze blame         # زمان هر سرویس
systemd-analyze critical-chain
uname -r                      # نسخه هسته
پیکربندی GRUB2
# ویرایش تنظیمات (نه grub.cfg!)
sudo vi /etc/default/grub
# اعمال تغییرات:
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
# در UEFI مسیر ESP:
sudo grub2-mkconfig -o /boot/efi/EFI/fedora/grub.cfg
⚠️ هشدار

هرگز فایل grub.cfg را دستی ویرایش نکنید! فقط از /etc/default/grub تغییر دهید و با grub2-mkconfig بازسازی کنید؛ وگرنه تغییرات در بوت بعدی از بین می‌رود.

LVM — حجم‌های منطقی

زنجیره LVM: Physical Volume (PV) ← Volume Group (VG) ← Logical Volume (LV). مزیت اصلی: تغییر اندازه حجیمی و snapshot.

ایجاد LVM
sudo pvcreate /dev/sdb                    # ۱. PV
sudo vgcreate myvg /dev/sdb               # ۲. VG
sudo lvcreate -n mylv -L 10G myvg         # ۳. LV
sudo mkfs.ext4 /dev/myvg/mylv            # ۴. فایل‌سیستم
sudo mount /dev/myvg/mylv /data
echo '/dev/myvg/mylv /data ext4 defaults 0 2' | sudo tee -a /etc/fstab
افزایش حجم (مهم!)
sudo lvextend -L +5G /dev/myvg/mylv  # افزایش LV
# سپس فایل‌سیستم را بزرگ کنید:
sudo resize2fs /dev/myvg/mylv   # ext4
sudo xfs_growfs /dev/myvg/mylv  # XFS
Snapshot
sudo lvcreate -s -n mybackup -L 2G /dev/myvg/mylv
sudo mount -o ro /dev/myvg/mybackup /mnt/snap
sudo lvremove /dev/myvg/mybackup   # حذف snapshot

توابع و مدیریت خطا

#!/bin/bash
set -euo pipefail     # خروج در خطا + متغیر نامشخص

tmp=$(mktemp)
trap 'rm -f $tmp' EXIT   # پاک‌سازی هنگام خروج

echo "Script: $0, Args: $#, PID: $$"

۷. وظایف مدیریتی و دسترسی‌ها

Admin Tasks, Users, Permissions & Quotas

مدیریت کاربران و گروه‌ها

ایجاد / حذف کاربر
sudo useradd -m -s /bin/bash -G sudo john  # Ubuntu
sudo passwd john                          # رمز
sudo usermod -aG docker john              # گروه اضافه (-a!)
sudo chage -M 90 john                     # انقضای رمز ۹۰ روز
sudo userdel -r john                      # حذف + home
id john
گروه‌ها
sudo groupadd developers
sudo gpasswd -a john developers    # add
sudo gpasswd -d john developers    # remove
groups john
sudo groupdel developers
⚠️ هشدار

در usermod -aG حتماً -a را بگذارید؛ بدون آن کاربر از تمام گروه‌های قبلی حذف می‌شود.

فایلمحتوا
/etc/passwdکاربران: name:x:UID:GID:home:shell
/etc/shadowرمز هش‌شده + سیاست رمز
/etc/groupگروه‌ها: name:x:GID:members
/etc/skelقالب دایرکتوری خانه

مجوزهای فایل — Permissions

ساختار: نوع فایل + مالک + گروه + سایرین. مقادیر عددی: r=4, w=2, x=1.

chmod / chown
chmod 755 script.sh   # rwxr-xr-x
chmod 644 file.txt    # rw-r--r--
chmod u+x script.sh   # افزودن x مالک
chmod -R 755 /var/www # بازگشتی
chown john:developers file
chown -R john:www /var/www
chgrp developers file
مجوز خاصعددمعنا
SUID4000اجرا با مجوز مالک (مثل passwd)
SGID2000اجرا با گروه / ارث گروه در دایرکتوری
Sticky Bit1000فقط مالک حذف کند (مثل /tmp)
مجوزهای خاص
chmod 4755 script.sh    # SUID
chmod 2755 dir/         # SGID
chmod 1777 /tmp         # Sticky bit
find / -perm -4000 -type f 2>/dev/null   # یافتن SUID
⚠️ هشدار

فایل‌های SUID با مجوز root اجرا می‌شوند. هرگز روی فایل‌های غیرضروری ندهید و مرتباً بررسی کنید.

ACL — کنترل دسترسی دقیق

setfacl / getfacl
getfacl /data/file                # مشاهده
setfacl -m u:john:rwx /data/file  # دسترسی کاربر خاص
setfacl -m g:dev:rx /data/file    # دسترسی گروه خاص
setfacl -x u:john /data/file      # حذف
setfacl -b /data/file             # حذف همه
setfacl -d -m g:dev:rx /data/     # ACL پیش‌فرض
💡 نکته

علامت + در انتهای مجوزهای ls -la (مثل -rw-rwx---+) یعنی فایل ACL دارد.

Quota و sudo و umask

Quota

quota -u john
sudo repquota /data
sudo
sudo visudo    # ویرایش امن
# user  ALL=(ALL)  NOPASSWD: ALL
# %wheel ALL=(ALL) ALL
# user ALL=(root) /usr/bin/systemctl restart nginx
sudo -l        # دسترسی‌های خود
umask
umask            # معمولاً 0022
umask 027
# فایل: 666-027=640  دایرکتوری: 777-027=750
echo 'umask 027' >> ~/.bashrc

[Unit]

After=network.target

[Service]
Type=simple
User=appuser
ExecStart=/opt/app/start.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now app

SELinux

SELinux یک سیستم امنیتی اجباری (MAC) است. سه حالت: Enforcing (اعمال)، Permissive (گزارش)، Disabled.

وضعیت و مدیریت
getenforce          # حالت فعلی
sestatus            # جزئیات
sudo setenforce 0   # Permissive (موقت)
sudo setenforce 1   # Enforcing (موقت)
ls -Z /var/www/html/       # context فایل
sudo audit2why < /var/log/audit/audit.log   # توضیح مشکل
sudo restorecon -Rv /var/www                # اصلاح context
📌 تغییر دائمی

در /etc/selinux/config مقدار SELINUX= را تغییر دهید و ری‌استارت کنید.

AppArmor

مدیریت profile
sudo aa-status

sudo aa-disable /etc/apparmor.d/usr.sbin.nginx   # غیرفعال
